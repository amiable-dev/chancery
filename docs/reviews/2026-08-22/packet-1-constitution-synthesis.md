# Council review — consolidated adversarial findings

Four reviews were run and cross-ranked. Below is the merged result: every finding that survived peer scrutiny, with location. **Three claims raised in review were rejected as misreadings and are not findings** — (a) that `SCOPE §7` in the Components table is a mis-citation of invariant 7 (§7 is a document section, not the invariant number); (b) that `assess → discard` violates "nothing deletes automatically" (the diagram says `(recommendation)`); (c) that the diagram's `draft task` arrow misuses the `--draft` flag (it names a task, not a flag). Chasing those would waste build time.

## 1. `architecture/overview.md`

**Verdict: REJECT** — three statements in this document would directly misdirect the next build (canon boundary, network-verb inventory, gate determinism), and its ADR cross-references do not resolve.

1. **[BLOCKER] §3 Components, Corpus row makes untrusted inflow canon.** "`concepts/`, `flashcards/`, `staging/` | the knowledge; canon" — §2 labels the same directory "untrusted inflow", subject to a `discard` recommendation. Unjudged, possibly-adversarial material cannot be canon under ADR-003 without collapsing the canon/quarantine distinction that `validation-r1a`'s provenance classes depend on. Split the row; state whether `verify` applies KB codes inside `staging/`.
2. **[BLOCKER] §2/§4: `kb ingest` is a network verb and is not declared one.** §2 shows "`URLs ──kb ingest──► staging/`"; §4 lists only "`sources / revalidate` … (network verbs — never in CI)". Either the inventory is wrong or the diagram is. This matters because that inventory is the list defining what must stay out of the gate path — and it hides the credential question (see ADR-001 §5).
3. **[BLOCKER] §2/§3: queue ageing makes `verify` clock-dependent.** "`.kb/queue/*.jsonl` (ageing = KB011)" plus "ageing gives it teeth" means a commit that is green today goes red later with no change to the tree, and re-running CI on an old commit fails. Name the authoritative clock, or compute age from a committed field against a committed budget, or move age-based policy out of `verify`.
4. **[BLOCKER] §3 decision provenance does not resolve.** The Ontology row cites "ADR-004/005/006"; the Queue row maps ADR-005 to `005-proposal-queue.md`. One attribution is wrong. Separately: ADR-009 is cited by ADR-002's Consequences and ADR-003's `links:` but appears nowhere in this map (validation is listed only as a *pending design spec*), and ADR-007 is referenced by nothing. A system map that does not map its own decision set cannot be used to check coherence.
5. **[BLOCKER] §5: "96% of citations hashed" is incompatible with "(P0–P9, all CI-green)"** unless source hashing is not gate-enforced, or an undocumented waiver exists. Either way the drift story in §2 ("hashed srcs", `revalidate`) is advisory, not enforced. Document the exemption path and its code, or the enforcement.
6. **[SHOULD-FIX] §1/§3 do not define the write boundary.** "A deterministic CLI (`kb`) owns every mutation" versus §2's `PR contract` inflow and §3's "writes are propose-only off-box". Who may modify canonical files, what applies an off-box proposal, and is a proposal itself canon? "Off-box" is never defined.
7. **[SHOULD-FIX] §4 vs §3: `cards` is both core and not core.** §4's "the knowledge loop" is "ingest → assess → promote → **cards** → link", while §3 says the learning extension is "outside core by decision (SCOPE §7)" and §5 lists `flashcards/` as canon. Pick one.
8. **[SHOULD-FIX] §5: the `log` spec collides with the invariants it is filed under.** "append-only `log.md` — what was *learned*" is historical content in a live file, against "history in git/derived", lean live notes, and note-granular lifecycle. It has no promotion, supersession, citation, or verify path. Classify it as derived/bounded, or drop it from the architecture until it has one.
9. **[SHOULD-FIX] §4: "stable error codes `KB001–KB014`" is a closed enumeration that the next build breaks.** `validation-r1a` (URL-liveness taxonomy, per-citation verdicts), `audit`, and `mcp-facade` each need new findings. Combined with ADR-002's "a verify code, once published, is a compatibility surface", there is no allocation, deprecation, or semantics-freeze rule anywhere — and no document links a canonical KB001–KB014 registry with remedies.
10. **[SHOULD-FIX] §2: `discard` has no owner and no mechanism.** No verb in §4 acts on a discard recommendation, and "Nothing deletes automatically, ever" applies. `staging/` therefore grows without bound. State the disposition path.
11. **[SHOULD-FIX] §2: "reciprocal backlinks (additive only)" + "Nothing deletes automatically, ever" leaves no way to retract a wrong edge.** Stale backlinks become permanent canonical assertions. Add a gated unlink/supersede operation.
12. **[SHOULD-FIX] §6 misquotes the invariants it declares non-negotiable.** It renders invariant 1 as "model-free CLI", dropping "pluggable judgment suppliers" — the half that constrains ADR-010 and the MCP facade. It also claims "each traces to an ADR here"; invariant 7 (internal citations never corroborate) traces to nothing in this packet. Quote SCOPE §4 verbatim.
13. **[SHOULD-FIX] §5's metrics are unauditable snapshots.** "96%", "all 244 concepts", "0 isolated notes", "42 harness-adapter files", "13 suites", "P0–P9" — six countable claims, no generating command, no commit. At least one will be false at the next merge. Link a generated report or delete them.
14. **[SHOULD-FIX] §4: "Crashes are JSON too" is an absolute the runtime cannot honour** (OOM, loader/syntax failure before the handler, SIGKILL, a throw inside the serialiser). Scope it: "all errors reaching the top-level handler", plus a documented unstructured-failure exit range.
15. **[SHOULD-FIX] Undefined load-bearing vocabulary in a published open-source doc:** "the pivot's core", "the *optimised persisted memory* interface", "the pattern's Lint", "FTS5 rung", "Gear 2", "off-box". None are defined or linked. Several also read as product framing, against Gear 2's no-product-claims scope.
16. **[NIT] Header: "**Status:** current as of 2026-08-22"** is hand-maintained freshness metadata that rots silently — the exact class ADR-003 Decision 4 bans. Use a commit id or drop "current".
17. **[NIT] "**Supersedes** `docs/kb-pipeline-design.md`"** is not a link, is path-ambiguous from `architecture/`, and supersedes the working description while this document's own review is "pending".
18. **[NIT] §2's "citations checked" under `kb query`** is ambiguous against invariant 7: checked for existence/navigability, or for support? The two readings have opposite consequences for "grounded query".

**Cross-document (this doc named first):**

No document gives it a class.

At minimum: name the review artefacts, and move the tool pin out of the system map.

**Most important thing MISSING:** an artifact-and-writer matrix — every path classified as canonical note, canonical configuration, quarantine (`staging/`), operational state (`.kb/queue/`), immutable evidence, judgment task/answer artifact, or rebuildable projection, with the only operations permitted to change each.

## 2. `adrs/001-two-phase-judgment-protocol.md`

**Verdict: REJECT** — the ADR's only quantitative evidence argues for the option it rejects, and the protocol has no trust or transaction model.

1. **[BLOCKER] Context force 3 supports the rejected option.** "*LLM-at-mutation-time inside a deterministic pipeline* won overall at 91.7–93.2%" describes precisely "**CLI calls a model internally**", rejected two paragraphs later. Nothing cited distinguishes an in-process call from an out-of-band task/answer exchange, so the number does not discriminate accepted from rejected. Either show the study's winning configuration *is* the two-phase protocol, or demote it from "Empirical support" to background.
2. **[BLOCKER] No trust model for phase-2 answers.** "validates the answer against its schema and applies it **by rule**" — schema conformance is syntactic. A defective or adversarial supplier (or a prompt injection carried in the phase-1 payload, which originates in `staging/`) can return a well-formed verdict that promotes poisoned material, rewrites classifications, or writes outside the task's intended scope. The founding incident *was* an automated pass damaging notes; this protocol reproduces that class through the supplier channel. Required: path confinement, field allowlists, size limits, a declared allowed write set per task, post-apply re-verify.
3. **[BLOCKER] No binding between task, answer, and repository state.** `--verdict/--draft/--answer <file>` requires no task ID, protocol/schema version, input hash, base commit, or answer digest. An answer can be applied to inputs that have since changed, or to the wrong task. This is a straightforward TOCTOU/misapplication defect.
4. **[BLOCKER] "replayable" is asserted without idempotency.** Re-applying an additive merge or a promotion must be either idempotent or refused. Add operation IDs, already-applied detection, and base-state checks.
5. **[BLOCKER] `status: accepted` with `council_review: pending (packet 1)`, while the body cites council output as evidence** ("The measured refusal of the alternative: council reviews 2026-08-22"). An accepted ADR cannot rest on a review its own frontmatter says has not happened, and "council reviews" names no packet, verdict, or artefact.
6. **[SHOULD-FIX] Atomicity and rollback are absent.** A multi-file promotion or reciprocal-link update can fail after partial writes. Require staging, whole-operation validation, atomic replace, and rollback or a recoverable journal.
7. **[SHOULD-FIX] "holds no API key" is a global absolute that breaks on the network verbs.** `ingest`/`sources`/`revalidate` will need rate-limited or authenticated fetches. Narrow to "holds no *model-provider* credential", and say where fetch credentials live and how they are unreachable from the gate path. The same sentence is also asymmetrically scoped — "never invokes a model, holds no API key, and makes no network call **in the gate path**" — inviting the reading that non-gate model calls are permitted.
8. **[SHOULD-FIX] "The task/answer schemas become load-bearing contracts — versioned with the ontology" has no compatibility rule.** What happens to an in-flight task when `kb migrate` bumps the ontology? Can an old answer replay against a new schema? Which code rejects a stale-schema answer?
9. **[SHOULD-FIX] The options list is a two-item strawman.** Missing and unrefuted: (a) deterministic CLI with an *optional* model adapter, hard-disabled in CI; (b) local sidecar model with no external credential. Both are the obvious rebuttals given force 3.
10. **[SHOULD-FIX] Author-as-judge / separation of duties is unaddressed.** The agent that staged the content can answer its own promotion task, and supplier anonymity makes this undetectable afterwards. State a policy even if unenforced at this gear; and reconcile anonymity with the operational need to trace systematic supplier failure (a non-canonical supplier/version record).
11. **[SHOULD-FIX] No failure semantics.** No supplier available; repeated invalid answers; two suppliers disagreeing — block, queue, escalate to human? Which KB code? Nothing stated.
12. **[SHOULD-FIX] "task and answer are files" does not establish a storage class.** Where do they live, are they committed, retained, redacted (they may embed untrusted or paywalled source text), canon or audit artifact?
13. **[NIT] "four agent harnesses" are never named**; overview §3 lists six adapter targets.
14. **[NIT] Unfalsifiable numbers in a falsifiability-pitched system:** "5% on semantic tasks" names no metric, task set, or n; "Karpathy's LLM Wiki premise" is uncited. Frontmatter `links` also mixes path styles (`"../SCOPE.md"` vs bare `"002-…md"`).

**Cross-document:**
15. **[SHOULD-FIX] adrs/001 ("Every judgment is inspectable … and replayable") ↔ adrs/003 (files canon; derived is rebuildable).** Judgment artifacts are neither note content nor rebuildable from the resulting note. They have no class in either document.
16. **[SHOULD-FIX] adrs/001 force 1 ("wrong under multi-agent unattended writes") ↔ adrs/003 Consequences ("true concurrent-writer support is explicitly out of scope at this gear").** The founding rationale exceeds the accepted scope unless both documents distinguish *sequential* multi-agent writes (in scope) from *concurrent* writers (out).

**Most important thing MISSING:** a normative protocol envelope — task ID, protocol/schema version, base commit and input hashes, declared allowed write set, operation ID, atomic-apply and rollback semantics — plus the trust boundary stating what a schema-valid malicious answer is structurally prevented from doing.

## 3. `adrs/002-ci-is-the-contract.md`

**Verdict: APPROVE-WITH-CHANGES** — the shape is right; three load-bearing terms ("hermetic", "the contract", "recorded evidence") are underspecified in ways the next build phase will hit immediately.

1. **[BLOCKER] "The gate is hermetic" is defined only against the network.** Decision 2: "`kb verify` never touches the network … This is what keeps CI deterministic." Determinism also requires independence from wall clock, timezone, locale, environment variables, randomness, filesystem iteration order, symlinks, Node version, git configuration and history depth, and subprocess execution. Replace the one-line claim with an enumerated list of forbidden inputs and declared permitted ones — and resolve the clock case, because queue ageing (overview §2, "ageing = KB011") reads it.
2. **[BLOCKER] The gate is self-attesting and unprotected.** "CI runs the gate tests before running the gate" does not defend against a single PR that weakens `.kb/lib/` and the both-polarity fixtures in `.kb/test/` together — in a repo whose own Context says an agent "invents fixes to make the red text go away". Nothing here requires CODEOWNERS, branch protection, a required check pinned to the tested commit, fork-PR policy, external golden fixtures, or execution of a pinned released verifier. As written, the contract is editable by the party it constrains.
3. **[BLOCKER] "Network verbs … write *recorded evidence*; verify checks the records" has no authority or freshness model.** Nothing states what `verify` does with a *missing*, *stale*, or *expired* record — fail, queue, or pass with a warning. Without that, the hermeticity rule is fully compatible with a gate that checks nothing, and this is exactly the substance of `validation-r1a`. Freshness expressed in wall-clock also re-opens finding 1; say explicitly whether `verify` checks only integrity and a separate job enforces refresh policy.
4. **[SHOULD-FIX] The ADR never states that `verify` is read-only.** Hermeticity does not forbid mutation. Forbid canonical writes outright and confine any temp files to a deterministically cleaned directory.
5. **[SHOULD-FIX] "A verify code, once published, is a compatibility surface" creates an obligation the ADR does not discharge.** No allocation rule beyond KB014, no deprecation window, no statement of whether *semantics* (not just numbers) are frozen, no statement of whether exit-code mapping is part of the surface, and no link to a registry.
6. **[SHOULD-FIX] Decision 1 juxtaposes two claims that read as contradictory.** Adapters "are explicitly not an enforcement mechanism; a stale adapter is itself a verify failure (KB014)" — adapter *state* is enforced. Say precisely: adapter *content* is unenforceable at authoring time; adapter *freshness* is gate-enforced. Also state the remedy (local regeneration + commit) and that CI must never regenerate, since files are canon.
7. **[SHOULD-FIX] "Parity across harnesses is enforced at the gate" overstates what a gate can establish.** It enforces repository acceptance criteria, not equivalent authoring behaviour, capability, or error handling across harnesses.
8. **[SHOULD-FIX] Decision 3: "every finding names file, field, and an explicit permitted remedy" does not fit repository-level failures** — missing files, duplicate IDs, cross-file cycles, workflow misconfiguration. Define nullable/multi-location findings rather than forcing a misleading `field`. Also: "permitted" implies a closed remedy vocabulary; link it or say "suggested".
9. **[SHOULD-FIX] "JSON outside a TTY" is an unreliable machine-interface rule.** Agents run under pseudo-TTYs; humans pipe. Provide an explicit `--json` that is stable regardless of terminal detection, and require adapters and CI to pass it.
10. **[SHOULD-FIX] "even crashes emit JSON"** cannot cover pre-handler loader/syntax failures, OOM, signals, or native faults. Bound the guarantee (see overview finding 14).
11. **[SHOULD-FIX] The contract has no verdict for the third state.** Overview §3 calls the queue "the third state between pass and block"; this ADR does not say whether `verify` exits 0 with unreviewed proposals pending, fails, or emits a queue-specific code. A contract with an undefined third outcome is not yet a contract.
12. **[SHOULD-FIX] Two forward references outrun their governance.** "The hermeticity rule constrains ADR-009's validation design" — ADR-009's status is unstated and overview lists validation only as a pending spec; and "future lineage checks" pre-classifies R1b, which overview lists under "Gated (SCOPE §3/§5 triggers)".
13. **[NIT] "the 42-adapter staleness class"** puts a file count in a normative decision record; it will be wrong at the next adapter.

**Cross-document:**
14. **[BLOCKER] adrs/002 Decision 2 ↔ architecture/overview.md §2/§3.** Hermeticity as the guarantor of CI determinism versus KB011 queue ageing. See overview finding 19.
15. **[SHOULD-FIX] adrs/002 ("recorded evidence") ↔ adrs/003 Decision 1.** Live-web evidence is authoritative for gate outcomes yet not deterministically rebuildable from files+git; ADR-003 admits no such category.
16. **[SHOULD-FIX] adrs/002 Decision 2 ("`sources`, `revalidate`, future lineage checks") ↔ architecture/overview.md §2 (`kb ingest` fetching URLs).** The enumeration that defines what must stay out of the gate path is incomplete.

**Most important thing MISSING:** a CI threat model — who may change `.kb/lib/`, `.kb/test/`, and the workflow; how a reviewer detects that green was bought by weakening fixtures; merge-enforcement and fork policy; the enumerated environmental inputs; and read-only execution.

## 4. `adrs/003-files-are-canon.md`

**Verdict: APPROVE-WITH-CHANGES** — the boundary rule is sound and well argued; two of its four decisions contain exceptions that dissolve them, and the granularity claim is already false for the next build.

1. **[BLOCKER] Decision 2's central identity is already contradicted inside this document.** "frontmatter lifecycle works exactly while *unit of versioning = unit of citation = unit of lifecycle*" and "Claim-level lifecycle — no" versus Consequences: "per-citation evidence records" — and `validation-r1a` ships "per-citation support verdicts" next. A citation is a sub-note unit. State where per-citation records live (derived projection? sidecar? frontmatter list?) and argue why that is not claim-level lifecycle under another name. Without this, invariant 4 is violated by the very next build and the ADR reads as retroactively wrong.
2. **[BLOCKER] Decision 2's escape hatch contradicts Decision 1.** "or the semantics live in a derived projection" places authoritative lifecycle semantics in a layer that Decision 1 says is "**never** the source of truth". This is only coherent if the derived semantics are deterministically inferred from canonical fields; otherwise the fact must be split into a note. Say so.
3. **[BLOCKER] Decision 4's exception swallows Decision 4.** "no `valid_from`/`valid_until` world-time fields **unless the source states them** — verify cannot check world-time claims." A source-stated date is still a world-time claim verify cannot check; the carve-out readmits exactly the metadata the invariant bans. The intended rule is almost certainly: source-stated times enter as *attributed claims bound to a citation or evidence record*, never as vouched frontmatter. Write that down, and require the pointer to the exact source statement.
4. **[BLOCKER] The canon/derived binary has no slot for the state machine around the corpus.** `staging/` (untrusted inflow), `.kb/queue/*.jsonl` (pending judgments — rebuildable *from what*?), network evidence records, and task/answer artifacts are none of: canonical note, canonical configuration, deterministically rebuildable projection. Overview §3 fills the vacuum wrongly by calling `staging/` canon.
5. **[SHOULD-FIX] "deterministically rebuildable from files+git" is asserted, never tested, and has no git-input contract.** Shallow clones (a common CI default), squash merges, rebases, rewritten history, tags, commit timestamps, `gc`, and git version can all change output. Specify required history depth and which git objects/metadata are canonical inputs — and add a verify check that rebuilds a derived layer and diffs it, or "never canon" is an honour system with undetectable drift.
6. **[SHOULD-FIX] Decision 2 stores the same relationship twice.** "Note-level `supersedes`/`superseded_by`/`status`" duplicates authority across two notes and recreates the failure used to reject fact-level frontmatter ("merge conflicts on exactly the shared fields"). Choose one authoritative direction, derive the reverse, and add a reciprocal-consistency check.
7. **[SHOULD-FIX] Decision 3 does not say where superseded content lives.** "superseded content is pointed to, never embedded" is incompatible with a superseded note that still contains its old text, unless "live notes" excludes superseded notes. If only git retains the text, `supersedes` must address a commit-qualified target. State whether superseded notes remain in the working tree and what pointers resolve to.
8. **[SHOULD-FIX] Context promises answers the Decision does not give.** "vendor critiques … name real ceilings — retrieval at scale, fact-level temporality, multi-writer — that **must be answered**"; then fact-level temporality is rejected, retrieval at scale is deferred to "the FTS5/derived-index rung (gated)", multi-writer is "explicitly out of scope at this gear". Downgrade to "must be acknowledged, with named gates and trigger conditions", or state the answers and their triggers.
9. **[SHOULD-FIX] The note-splitting escape hatch has no criterion, verb, or citation-repointing rule.** "if a fact genuinely needs an independent lifecycle it becomes its own note" — what triggers a split, who performs it (`kb migrate`? a two-phase verb?), how are inbound citations to the parent repointed? Unbounded fragmentation also cuts against invariant 5 and against "0 isolated notes" as a health metric.
10. **[SHOULD-FIX] The strongest claims in the document are uncheckable.** "Two adversarial council panels converged on the same boundary rule" and "(council, unanimous)" identify no panel, packet, or transcript — while frontmatter says `council_review: pending (packet 1)` on the same date and `status: accepted`.
11. **[SHOULD-FIX] "History lives in git" needs a retention assumption.** Squash merges, history rewriting, `gc`, shallow clones, and repository migration can destroy transaction time. Is preserving full history a governance requirement?
12. **[SHOULD-FIX] The FTS5 consequence overreaches.** "doubles as the future home for any claim-level querying" — a search index cannot create legitimate claim-level lifecycle semantics without canonical claim identity. Either remove the implication or define deterministic claim extraction and identity.
13. **[NIT] "the `_index.md` rule, scaled"** is a dangling referent carrying Decision 1's meaning, and Zep/Mem0 are named without citation — both problems for a published repo.
14. **[NIT] The title legislates one invariant; the Decisions enact three** (note granularity, token tax, no unverifiable metadata). Retitle or split.
15. **[NIT] `links` omits ADR-001/002** although Decision 4's justification ("verify cannot check world-time claims") depends entirely on ADR-002's hermeticity.

**Cross-document:**
16. **[BLOCKER] adrs/003 Decision 2 ↔ architecture/overview.md §5 (`validation-r1a`: "per-citation support verdicts", `audit`: "stale claims").** See overview finding 20. One of the two must be amended before build.
17. **[SHOULD-FIX] adrs/003 Decision 3 ↔ architecture/overview.md §5 (`log` spec).** An append-only learned-history file in the live tree against "live notes stay lean" and "History lives in git and derived layers".
18. **[SHOULD-FIX] adrs/003 Decision 1 ↔ adrs/002 Decision 2.** Recorded network evidence determines gate outcomes but is not rebuildable; ADR-003 offers no immutable-canonical-evidence category.
19. **[SHOULD-FIX] adrs/003 Consequences ↔ adrs/001 Context force 1.** Concurrent writers out of scope versus multi-agent unattended writes as the founding motive. See ADR-001 finding 16.

**Most important thing MISSING:** the placement rule for sub-note evidence — a normative data-classification table naming canonical notes, canonical configuration, quarantine, operational queue state, immutable evidence records, judgment audit artifacts, and rebuildable projections, with per-citation verdicts assigned to exactly one of them.

## The three things to fix before any code is written

1. **The data-classification table** (blocks overview, ADR-003, and `validation-r1a` simultaneously): staging, queue, evidence records, task/answer artifacts, per-citation verdicts. Four documents currently disagree or are silent, and the next spec is the one that needs it.
2. **Determinism scope for `verify`** (blocks ADR-002 and overview): enumerate permitted inputs, resolve queue ageing, declare read-only, and state the policy for missing/stale evidence.
3. **The two-phase transaction envelope and trust boundary** (blocks ADR-001): task↔answer↔commit binding, allowed write set, atomicity/rollback, and what a schema-valid adversarial answer cannot do — plus removing or re-scoping the empirical citation that currently argues for the rejected option.
