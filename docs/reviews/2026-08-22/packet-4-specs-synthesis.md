# Council review — packet 4 (six design specs)

**Verdict convention used below:** `REJECT` = contains at least one blocker that cannot be closed by adding specification — the doc's central mechanism must change. `APPROVE-WITH-CHANGES` = blockers are fillable gaps; the shape holds.

---

## 1. `design/validation-r1a.md` — **REJECT**

1. **[BLOCKER] §1 and §4 are mutually exclusive as written.** §1: "every citation carries a state, states come from the enum." §4 introduces `internal-synthesis` and `model-inference` sources, which have no URL and can never be fetched. Post-migration, KB015 ("citation missing liveness state") either fires on every internal source or forces a fabricated state. Scope KB015 to URL-bearing source kinds, or add an explicit `not-fetchable` member — and then scope `likely-fabricated` inference to URL-bearing sources only.
2. **[BLOCKER] `likely-fabricated` has no legal storage model.** "derived: N consecutive failures from first sight" requires a persistent history of network observations. In the note, it is exactly the unverifiable world-time metadata SCOPE §4.6 forbids, and hermetic verify cannot corroborate it. In a derived layer, SCOPE §4.3 requires rebuildability — a failure history cannot be rebuilt without the network or a clock. Name the store, its canon status, what writes it, and how `verify` treats it. `N` is also never given.
3. **[BLOCKER] `blocked` and `likely-fabricated` overlap with no precedence rule.** `blocked` = "citation fine, unverifiable by tool"; `likely-fabricated` = "never resolved on any check since first recorded." A permanently bot-blocked host satisfies both, and a single-valued enum cannot hold both. Worse, the label is an accusation derived from an observation that equally fits a typo, a deleted page, a paywall, or DNS failure — rename to a neutral `never-resolved` flag orthogonal to liveness, and state the state machine.
4. **[BLOCKER] §2 never says where "the **full extracted page text**" comes from.** If `kb support` fetches, it is a network verb and must be labelled alongside `sources`/`revalidate`; if it reads stored extraction, name the cache and define behaviour when extraction is absent, stale, `blocked`, or `dead-archived` (a Wayback *availability* check confirms a URL, not content — those citations are silently unjudgeable). No size ceiling, chunking rule, content-type restriction, or extraction version is given; a 20-citation note is an unbounded task payload.
5. **[BLOCKER] §2 has no binding between the emitted task and the submitted answer.** `kb support <slug> --verdicts v.json` requires no task id, corpus commit, citation id, evidence hash, section hash, or schema version, and defines no staleness rejection. A verdict computed against different content passes structural validation and is applied. This defeats the "validates and applies by rule" model.
6. **[BLOCKER] §4 claims mechanical enforcement of a rule with no referent.** "**Verify enforces the standing rule mechanically: internal classes never count toward any corroboration computation** (the computation arrives with R1b)." There is nothing to enforce in R1a; this is a no-op presented as a guarantee. Either say plainly "the field lands now, the rule is enforced in R1b," or specify a real R1a check (e.g. a note whose sources are all internal classes may not carry a corroboration-implying tier or claim).
7. **[BLOCKER] §2's embedded statistics are unsourced and argue against their own conclusion.** "snippet evidence has a measured 68% extraction-fault rate" and "Cheap models are adequate judges (F1 ≈ 0.71–0.75 vs frontier)" cite no dataset, corpus, or document. F1 0.71–0.75 on *evidence verdicts* is an argument for escalation, not for adequacy. And "the task instructions say so to permit inexpensive suppliers" puts supplier economics into the judgment prompt — prompt contamination biasing toward confident verdicts, and a product-shaped claim at Gear 2. Emit the task; keep supplier calibration outside the payload.
8. **[SHOULD-FIX] §1 imports the dependency the preamble disclaims.** Preamble: "nothing here needs the lineage resolver or confidence tiers (R1b, gated)." §1: "`likely-fabricated` on a `verified`-tier note is an error once tiers exist." Acceptance then promises "Both-polarity fixtures for KB015–017," which cannot cover this rule. Move it to R1b or delete the sentence.
9. **[SHOULD-FIX] §4's migration default asserts a class it does not know.** "everything else defaults `external-secondary` pending judgment" converts absence of classification into a positive provenance claim and hides the backlog from KB017 and from audit. Use an explicit `unclassified` sentinel.
10. **[SHOULD-FIX] §3's supersession model is asymmetric and under-constrained.** `supersedes: [slug…]` is a list, `superseded_by: slug` is scalar — a note split into two successors is inexpressible. "a superseded note's `status` must not be `stable`" names no required value. No acyclicity or chain-depth rule (A→B→A passes pairwise reciprocity). Reciprocal fields in two files need one atomic gated transaction with rollback, or a partial write leaves the corpus red. "targets must exist (KB new code)" is redundant with KB016 and reads like an editing artefact.
11. **[SHOULD-FIX] §3 mandates a destructive prose write with no verb.** "Superseded notes stay lean … a one-line pointer under the title" gutting a body is a canon mutation; no command is named and no gate path is specified.
12. **[SHOULD-FIX] §3 changes retrieval with no spec or test.** "`kb query` down-ranks superseded notes and says so in the hit" — no magnitude, no output field name, no acceptance criterion.
13. **[SHOULD-FIX] §5's severity switch has no mechanism.** "warning until migration completes, then error" needs a committed, in-repo migration-version signal that hermetic verify can read. Also undefined: does `verify` exit non-zero on warnings? Under ADR-002 ("CI is the contract"), unstated warning semantics make KB017 unenforceable either way.

**Most important thing MISSING:** a defined observation record for network-derived facts (first-seen, consecutive-failure count, snapshot URL, content hash) with its canon status, its writer, and its treatment by hermetic `verify` — without it `dead-archived` and `likely-fabricated` are unimplementable.

## 2. `design/context-compiler.md` — **APPROVE-WITH-CHANGES**

1. **[BLOCKER] Rule 1 contradicts Rule 2.** Rule 1: "same corpus state + same arguments ⇒ byte-identical output." Rule 2: "volatile fields — dates, hashes — segregated to the end." If those dates are a compile-time clock reading, the Acceptance determinism test cannot pass and SCOPE §4.6 is breached; if they are corpus-derived they are not volatile. State that the bundle contains no clock reading, and note that content hashes are integrity fields, not volatile ones.
2. **[BLOCKER] `--budget <tokens>` has no unit contract.** Token counts are tokenizer-specific. (Counting tokens does not itself violate the model-free invariant — a pinned, versioned tokenizer is deterministic and offline — but as written, two suppliers get different bundles from identical arguments, which kills Rule 1.) Name the tokenizer and version, and say whether the count covers the JSON wrapper or content only.
3. **[BLOCKER] Over-budget behaviour is undefined, and it is the common case.** Rule 3 trims "never mid-section" and forbids silent truncation; the target note alone routinely exceeds a small budget. Specify: fail with a code and a minimum-required size, or emit over budget with a declared overflow flag.
4. **[BLOCKER] The command signature does not fit its own task list.** `kb context <slug> --for <task>` versus `audit-pair` (two notes), `research-brief` and `query-answer` (no target slug, or a query string). The Command section already hedges with "target note(s)". Define per-task arity, or the first implementation grows ad-hoc overloads.
5. **[BLOCKER] Determinism is asserted over inputs that are not corpus state.** The bundle includes "existing derived artifacts (cards for cards-refresh, prior verdicts for audit)" and "related concepts via graph edges (1 hop, ranked)" — derived layers that may be stale, absent, or index-version-dependent. Choose: fail on stale derived layers, rebuild first, or pin a derived-layer version hash in the bundle. "Ranked" needs a stated total order with a deterministic tie-break (score, then codepoint slug); codepoint sorting fixes serialisation, not selection.
6. **[SHOULD-FIX] "the exact policy excerpts that bind the task" is the least deterministic clause in the doc.** Excerpt *selection* is judgment unless a committed task→policy-anchor mapping exists. Name the file, version it, and make dangling anchors a lint code — otherwise a heading edit silently changes every bundle.
7. **[SHOULD-FIX] Rule 2 legislates behaviour the CLI cannot enforce.** "Compile between sessions; append within… No mid-task recompilation" is harness policy, and it sits beside the non-goal "cross-session memory of what an agent already saw (harness's job)." Demote to consumer guidance, or define a bundle id clients must retain.
8. **[SHOULD-FIX] Trim reporting undermines the prefix claim.** Rule 2 sells "a stable prefix by construction"; Rule 3 requires the bundle to "report what was trimmed." State that all reports and diagnostics live in the volatile tail.
9. **[SHOULD-FIX] Acceptance covers one of five task modes.** A `kb-cards` refresh does not exercise `promote-review`, `audit-pair`, `research-brief`, or `query-answer`, or their policy mappings and artifact rules.
10. **[NIT] "aligning with prompt-cache economics rather than fighting them"** is an unverifiable performance claim in a Gear 2 doc that forbids product claims. State the structural property (fixed section order, volatile tail) and stop there.
11. **[NIT] Persistence status unstated.** "optimised persisted memory" implies persistence, but no output location, cache key, invalidation rule, or prohibition on committing bundles is given. Say explicitly: bundles and caches are derived, rebuildable, never canon. The default `--format` is also unspecified while Rule 5 requires data, not prose.

**Most important thing MISSING:** a versioned bundle schema (`schema_version`, section list, field types) plus the compilation algorithm — Rule 5 makes every harness skill depend on this shape.

## 3. `design/mcp-facade.md` — **REJECT**

1. **[BLOCKER] "the only write" is false within its own table.** `kb_propose` is annotated "**the only write**", yet the next row exposes `kb_submit(verb, target, answer)` for "any two-phase verb" — and the apply phase of e.g. `kb support --verdicts` "records into `sources[].support`" (validation-r1a §2), a canonical write. Rule 2's "No direct canonical writes" then either forbids `kb_submit` from applying (making the tool useless for off-box suppliers) or is wrong. Decide per tool: does submit *apply*, or only *stage for apply*? Note also that the real invariant is not "no canonical writes" but "no path around the gate" — a validated apply legitimately writes canon.
2. **[BLOCKER] The two-phase protocol has no task envelope.** `kb_task(verb, target)` / `kb_submit(verb, target, answer)` defines no task id, task hash, corpus commit, evidence hashes, schema version, expiry, idempotency key, or replay rejection. ("Stateless" at the server is fine — MCP carries connection-level init state — but then the *envelope* must carry all of it, and it doesn't.) A client can replay an answer or submit judgment computed against content that has since changed, entirely behind the gate.
3. **[BLOCKER] The acceptance round-trip names a step with no tool.** "a `kb_propose`→`kb_submit`→promotion round-trip" — there is no promotion or verify tool in the table. Either the test is impossible, or `kb_submit` promotes, contradicting finding 1.
4. **[BLOCKER] The integration proof is not hermetically testable.** "llm-council (Python) driving one full assess loop as the integration proof" makes the gate depend on an external repo and, implicitly, a live supplier. Split it: recorded-fixture parity test in CI, live loop as an out-of-gate smoke.
5. **[BLOCKER] No concurrency or worktree model.** An MCP server writing staging/queue while the CLI or CI runs `verify`, `migrate`, or `export` against the same worktree is the default deployment. Specify locking, behaviour on a dirty worktree / detached HEAD / mid-rebase, and repository selection (may a notebook target an arbitrary repo?).
6. **[SHOULD-FIX] The parity test cannot pass as written.** Acceptance: "`kb_search` result ≡ `kb query` phase-1 JSON," but the table says `kb_search` "returns hits with definitions + relationship edges." Either delete the extra promise or define and test the transform.
7. **[SHOULD-FIX] Rule 3 contradicts itself and dangles a reference.** "**Local only**: stdio transport … no network listener by default" implies a non-default listener exists, immediately after declaring remote out of scope. Say: no listener is implemented in this build. "trigger T4" cites no document.
8. **[SHOULD-FIX] "targets the 2026-07-28 MCP revision"** has no link, no minimum supported revision, and no stated behaviour when a client negotiates an earlier one.
9. **[SHOULD-FIX] "Local trust boundary only" is not a filesystem security model.** `kb_read(slug)` and `kb_propose` need: slug-index resolution only (never path join), path/symlink confinement, payload and note size limits, subprocess environment. Stdio does not make an agent-supplied string safe — and note content read via `kb_read` is untrusted input that can drive `kb_propose`, so state proposal rate/size limits and record the originating tool call on every proposal.
10. **[SHOULD-FIX] `kb_propose(kind, payload)` hides three unrelated write paths** — "`kb ingest` (url) / queue proposal / staging draft" — behind one untyped payload, with no per-`kind` schema and no statement of how ingest's network fetch failures surface. Likewise "any two-phase verb" needs a discoverable, versioned verb registry with typed argument objects; `(verb, target)` cannot express audit's `--check`/`--limit`, context's `--budget`, or pair targets.
11. **[SHOULD-FIX] Error parity is untestable as stated.** "an MCP client gets the same remedy strings CI does" makes human-readable prose an API surface. Specify stable codes and structured fields instead.
12. **[NIT] Field drift and unevidenced rationale.** `kb_search(query, domain?, maturity?, limit?)` uses `maturity` where the corpus vocabulary is `status`/tier (validation-r1a §1, §3). "resources/prompts surfaces (unused by clients in practice)" names no client — exclusion can simply be a scope decision.

**Most important thing MISSING:** the versioned, replay-safe task envelope binding every answer to a task id, corpus revision, and evidence hashes — everything else here is a thin wrapper; this is the only genuinely new mechanism and it is absent.

## 4. `design/audit.md` — **REJECT**

1. **[BLOCKER] "Report-only" plus "queues each finding" plus KB011 means every documented tension eventually reddens CI.** Rules: "`verify` does **not** fail on findings — a contradiction is often a tension worth documenting; only queue ageing (KB011) has teeth." Shape: "validates, writes `maintenance/YYYY-MM-DD-audit.md`, **and queues each finding**." There is no terminal disposition, so a corpus with a legitimate, deliberately-retained tension cannot stay green. Define `accepted-tension` / `wont-resolve` with a rationale, and the verify rule that exits the ageing clock.
2. **[BLOCKER] One finding schema cannot express five checks.** "A finding names both notes, quotes both claims, says which is more likely correct *and why*" — stale claims and missing provenance concern one note; a concept gap concerns ≥3 notes and has no pair of contradictory claims; graph-rot omission candidates concern an absent edge. Define discriminated per-check candidate and finding schemas.
3. **[BLOCKER] "vs note `date`" collides with SCOPE §4.6 and is ambiguous.** Which date — creation, revision, publication, source? An author-supplied frontmatter date is precisely the unverifiable world-time metadata the invariant excludes; a commit date is derived and unavailable in shallow CI clones. No reference "now" is defined either. Prefer deterministic signals (stored source drift, explicit version pins); any date comparison must name the field, its authority, and a declared reference date.
4. **[BLOCKER] Graph rot's temporal check has no data model.** "high-degree notes whose edges predate a supersession" — edges carry no timestamps anywhere in these specs, and git archaeology fails on squashes and shallow clones. Either derive ordering from committed supersession records rather than commit timestamps, or cut the check.
5. **[BLOCKER] Candidate generation is unspecified, so the determinism acceptance test cannot be written.** "top-k lexical neighbours" (no `k`, no similarity function, no index version, no tie-break); "terms in ≥3 notes" (no tokenisation, normalisation, or multiword rule); "decay-language regex" (pattern set not enumerated or versioned); "strong lexical pairs", "high-degree", "thin". Lexical similarity is legitimately deterministic and model-free — the defect is unpinned parameters, not the technique. Pin them, version them, and hash the parameter set into the task JSON so reruns are comparable.
6. **[SHOULD-FIX] The stale-claims input is network-derived.** "`kb revalidate` drift" is an observation, not corpus state. State explicitly that `kb audit` reads the stored observation record and never fetches, that it is not in the gate path, and that fixtures stub the record.
7. **[SHOULD-FIX] "validates" is undefined because there is no finding schema — and the cheapest, highest-value rule is absent.** Quoted claims must be verbatim substrings of the named notes at a stated content hash. That check is deterministic, free, and the only defence against fabricated quotes; it belongs in Rules and Acceptance. Findings also need binding to the emitted candidates (candidate ids, corpus commit, stale-answer rejection).
8. **[SHOULD-FIX] "says which is more likely correct *and why*" is unvalidatable free prose.** Constrain to an enum plus a bounded rationale field, and state that the rationale is never treated as corroboration (SCOPE §4.7).
9. **[SHOULD-FIX] The maintenance artifact is unspecified.** `maintenance/YYYY-MM-DD-audit.md`: date source and timezone, two runs the same day (overwrite / append / error), `--check contradictions` then `--check graph-rot` into the same file, canon or derived (SCOPE §4.3), and whether `verify` inspects it. Also, "Report-only, no exceptions" is contradicted by writing a file and mutating the queue — say "never edits concept prose" and specify atomicity/rollback for the writes it does perform.
10. **[SHOULD-FIX] "missing provenance | empty/thin `## Sources` — pure structure" is misfiled.** If it is pure structure it belongs in KB001–014 lint, not a semantic two-phase verb; "thin" has no threshold. It must also be class-aware, or a note whose sources are all `internal-synthesis` is certified as sourced, defeating SCOPE §4.7.
11. **[NIT] "~6 pairs/note, not 29,646 pairs"** hardcodes a corpus snapshot into a design doc. State the parameters (k, symmetric-pair dedup, domain bound) and drop the number.
12. **[NIT] ADR-010 is normative in Shape but absent from the header's ADR list.** Add it.

**Most important thing MISSING:** stable content-derived finding identity plus a suppression / accepted-tension record — without it, every run re-queues the same tensions and KB011 turns the corpus permanently red.

## 5. `design/log.md` — **REJECT**

1. **[BLOCKER] The doc's only enforcement mechanism is vacuous.** "`kb verify` checks both cheaply against `git show HEAD:log.md`." In CI the working tree *is* HEAD, so the comparison always passes; once a mutated or reordered line is committed, both sides agree and tampering is invisible. Compare against the merge-base with the default branch (or the branch's parent commit), and specify behaviour for the first commit, shallow clones, detached HEAD, and force-push.
2. **[BLOCKER] Pure append to one root file is incompatible with ordinary branching.** "Append-only, dates monotonic … newest last (pure append, no seek)" guarantees a conflict at the same trailing region whenever two branches both append, and resolving by interleaving reorders lines — which the spec says must fail verify. Either shard (per-day or per-branch files with a deterministic merge) or state how verify recognises a resolution commit as legitimate.
3. **[BLOCKER] Internal contradiction about authorship.** "It is the one file neither hand-authored nor regenerable" versus "Research provenance rides here too: `query` misses worth recording, gaps found by whitepaper work." `kb query` is not a mutating command and no verb writes those lines, so they are hand-authored — and since verify only checks immutability of prior lines, hand-appending is undetectable, making the claim both false and unenforceable. Pick: CLI-only (drop research provenance), or add a gated `kb log` / `kb record-gap` verb.
4. **[BLOCKER] "it commits with the change it describes" has no mechanism.** Nothing here stages or commits atomically, and the append-only rule forbids *change*, not *omission* — a canon-mutating commit with no log line passes verify. The checkable rule is missing: a canon-mutating diff must be accompanied by ≥1 new log line.
5. **[BLOCKER] Log dates are unverifiable world-time inside a canon file.** "dates monotonic, grouped by day" reads a local wall clock with no stated timezone or clock source, and hermetic verify cannot corroborate any of it (SCOPE §4.6). Either declare UTC dates as an explicit, argued exception with ordering checked intra-file only (never against "now"), or key entries to commit identity instead of dates.
6. **[SHOULD-FIX] "every mutating command appends one line on `--apply`" is unscoped.** Does `kb migrate` over 300 notes write 1 line or 300? Do derived rebuilds (`export`, index) log at all — they mutate files but not canon. Scope the rule to canon-mutating verbs, define bulk aggregation, and define event types with required fields so mechanical repairs are not forced to pretend learning occurred.
7. **[SHOULD-FIX] Partial failure and log-write failure are undefined.** A command that writes some files then errors: is the line written? A log asserting a change that did not fully land is the inverse of provenance. Every write path is now coupled to one hot file with no transactional story.
8. **[SHOULD-FIX] There is no line grammar.** Verb, target, disposition, rationale slot, and normalised encoding/newlines are all unspecified. Without one, verify can only check immutability, no consumer can parse the file, and "what was learned" degrades to prose. "No existing line may change" is also insufficient integrity: suffix deletion, line merging, or wholesale replacement need explicit prohibition.
9. **[SHOULD-FIX] "Every deferred day is provenance permanently lost" is overreach.** Commit messages, queue entries, audit files and support verdicts retain most of the deterministic half; only the rationale is irrecoverable. The rhetoric of irreplaceability is standing in for answers to findings 1–5 — separate the irrecoverable rationale fields from the reconstructable change summary.
10. **[SHOULD-FIX] Unbounded growth, no exclusions.** State that `log.md` is excluded from `kb context` bundles and from export output, and give a rotation scheme (`log/2026.md`) that survives the append-only check.
11. **[SHOULD-FIX] No content policy for a public Gear 2 repo.** Recording "`query` misses" captures private research questions verbatim, permanently, in a published repository. Define redaction, opt-in, and length limits.
12. **[SHOULD-FIX] Scheduled CI implies repo write access.** If CI runs `revalidate` or `audit`, those verbs mutate and must therefore append and commit. No document scopes that credential or its blast radius.

**Most important thing MISSING:** a git-aware append-verification design (base ref, merge policy, commit coupling) that stays valid *after* commit and under parallel branches — without it, the file's central promise is unenforced.

## 6. `design/export-integration.md` — **APPROVE-WITH-CHANGES**

1. **[BLOCKER] There is no publication filter.** "`kb export docusaurus` emits a standalone tree" says nothing about *which* notes and directories ship. As written, drafts, staging content, superseded stubs, `queue`, `log.md`, and `maintenance/YYYY-MM-DD-audit.md` — files whose content "says which is more likely correct *and why*" about the owner's own corpus — fall inside scope and go public at Gear 2. Specify an allow-list by `status` and path, and make it verify-checked.
2. **[BLOCKER] The pull model without pinning defeats the doc's own reviewability argument.** "The site's CI checks this repo out and runs the export during its own build" plus "Release-artifact pinning is the later hardening step, not the start" means the site builds against a moving `main` *and* a moving transform layer, so "Output deterministic — that's what makes the integration diff reviewable" fails at the delivery boundary. Requiring a pinned tag or commit SHA is one line of site config; make it day one. Relatedly, "Public repo at Gear 2 removes the deploy-key question" is a non-sequitur — it removes a read-credential problem and creates a supply-chain one (the host's CI now executes this repo's exporter). Name that trade.
3. **[BLOCKER] The manifest cannot support "diffs instead of rebuilding".** "`kb-export-manifest.json` (slug → content hash)" — hash of the source note or the rendered output? If source, a transform-layer, template, base-path, id-prefix, facet, or tag-merge change produces identical hashes and a permanently stale site. Hash rendered outputs and include transform/renderer/config/schema versions.
4. **[SHOULD-FIX] `--merge-tags` has no host-tags contract and conflicts with "standalone tree".** It "merge[s] into the host's `tags.yml`" without saying whether the host file is inside `--out`, a parent, or a separate argument — i.e. it may write outside the export directory, potentially over source files. Define an explicit input/output pair and atomic behaviour.
5. **[SHOULD-FIX] Conflict severity is undefined where it matters.** "conflicts are *reported*, never silently overwritten" — reported to which stream, with which exit code, and is partial output left behind? Since "This repo's CI keeps running the export as a build check," a conflict must fail that check or reporting is decoration.
6. **[SHOULD-FIX] `--out DIR` has no filesystem safety contract.** Nothing prevents export into `concepts/`, `.git`, or a symlinked path, and nothing defines overwrite, cleanup, partial-failure rollback, or atomic directory replacement. Generated writes must not become a route around the canonical write gate.
7. **[SHOULD-FIX] The link-rewrite contract is incomplete.** "`--base-path` — site-absolute link rewriting" says nothing about anchors, aliases, images and binary assets, relative markdown links, external URLs, URL encoding, trailing slashes, or unresolved links — exactly the failure class the command exists to fix. `--id-prefix` is also optional despite id collision being a stated motivating break: give it a safe default (or require it for mounted exports) and specify post-prefix normalisation and collision detection.
8. **[SHOULD-FIX] "One transform layer, N renderers" overreaches across `kb export json`.** "wikilink resolution, facet flattening, H1 handling and the manifest are shared" — facet flattening and H1 handling are presentation transforms that are wrong for a machine consumer. Specify the JSON schema, its stability guarantees, and what source structure it preserves, independently.
9. **[SHOULD-FIX] The renderer-neutral claim is Docusaurus-shaped.** "breaks three ways: relative links… `id: index`… `tags.yml`" are all Docusaurus faults; mkdocs is shown with only `[--base-path …]`, has no `tags.yml` and no `id:` concept, and its own nav/slug collisions with a host are unhandled. State per-renderer flag applicability and the error on an inapplicable flag.
10. **[SHOULD-FIX] Determinism omits environmental inputs.** Line endings, file modes, locale, path normalisation, directory ordering, Node and renderer versions, and whether absolute source paths may appear in artifacts.
11. **[SHOULD-FIX] Missing the one-line invariant that export output is never canon and is never re-ingested** (SCOPE §4.3). Without it, a site-side fix in the exported tree becomes a second source of truth — the classic failure of this pattern.
12. **[NIT] "Round-trip test on a fixture host site" is the wrong term** — nothing is imported back. Also, the fixture site pulls an npm tree; state the pinned version and the offline/cached posture or this will be the flakiest test in the gate. Acceptance covers neither mkdocs nor the JSON renderer.

**Most important thing MISSING:** the publication policy — which statuses and directories may ship, and how superseded stubs and provenance are rendered — for a corpus whose internal artifacts include contradiction findings and unverified sources.

## Cross-document contradictions

1. **[BLOCKER] `validation-r1a.md` §2 × `audit.md` Rules.** validation-r1a routes `UNCERTAIN`/`CONTRADICTED` to the queue; audit.md queues every finding while asserting "`verify` does **not** fail on findings … only queue ageing (KB011) has teeth." Every support verdict and audit finding therefore becomes a *delayed* CI failure, and neither doc defines an accepted/terminal disposition. A corpus with legitimate unresolved tension cannot stay green. Fix in both docs, once.
2. **[BLOCKER] `validation-r1a.md` §4/KB017 × `audit.md` "missing provenance".** The same word names two mechanisms with two severities: a deterministic verify error for a missing `sources[].class`, and a semantic, queued judgment for "empty/thin `## Sources`". Additionally, audit's structural check is not class-aware, so a note sourced entirely by `internal-synthesis` passes it — certifying self-reference as provenance, against SCOPE §4.7. Assign each concept to one mechanism with distinct codes.
3. **[BLOCKER] `context-compiler.md` × `mcp-facade.md`.** context-compiler's premise is "so all harnesses work from identical input", yet mcp-facade's table has no `kb_context` — and its stated consumers ("the deep-research workflow, Python tooling (llm-council), notebook users") are precisely the harnesses "a shell can't reach cleanly." Add the tool or retract the claim.
4. **[BLOCKER] `log.md` × `mcp-facade.md`.** log.md: "Written by the CLI: every mutating command appends one line on `--apply`." MCP's `kb_propose`/`kb_submit` have no `--apply` and no actor identity, so writes over MCP produce no log line. Either the engine (not the CLI) owns the append, or SCOPE §4.8's "writes go through the gate on every interface" is broken for provenance.
5. **[SHOULD-FIX] `context-compiler.md` × `audit.md`.** The compiler consumes "prior verdicts for audit" as an existing derived artifact; audit.md's only outputs are prose `maintenance/YYYY-MM-DD-audit.md` plus queue entries. No machine-readable verdict artifact exists. One of the two docs must define it. (Also: `audit-pair` appears as a compiler task while audit.md itself emits "pairs/terms + the text needed to judge" — two owners for the same assembly.)

## Claims raised in review and dismissed (do not chase these)

- **Token budgeting does not violate the model-free invariant.** A pinned, versioned tokenizer is deterministic and offline. The defect in `context-compiler.md` is the missing tokenizer contract, not the feature.
- **Lexical candidate generation does not require an embedding model.** BM25/TF-IDF/token-overlap are deterministic. The defect in `audit.md` is unpinned parameters, not model coupling.

- **SCOPE §4.6 forbids *unverifiable world-time* metadata, not all dates.** Corpus-derived or explicitly-supplied dates are legal. The defects are where date provenance and semantics are left unspecified (`log.md` monotonic dates, `audit.md` "note `date`", the context bundle's volatile tail).
