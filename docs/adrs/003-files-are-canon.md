## Context

The substrate question: markdown files vs a database as source of truth, and at what granularity temporal and validation semantics live. Adversarial review (artifacts: [`../reviews/2026-08-22/`](../reviews/2026-08-22/)) converged on a boundary rule — and then, on second review, exposed that a bare canon/derived binary cannot classify the system's own artifacts: quarantine, queue state, network evidence, and judgment records are none of "canonical note" or "rebuildable projection". The full class system now lives in [data-classification.md](../architecture/data-classification.md); this ADR fixes the rules the classes implement.

## Options considered

Database-as-canon (rejected: abandons the substrate thesis); fact-level bi-temporality in frontmatter (rejected: "a database expressed in YAML, whose query engine is grep" — merge conflicts on shared fields, full-scan temporal queries, dual truth with git); **files-canon + explicit class system + note-granular lifecycle** — accepted.

## Decision

1. **Files are canon; projections are rebuildable and never authoritative** — and the class table is the complete enumeration: C5 evidence records are *append-only observation history* (authoritative for what was observed, exempt from rebuildability **by class**, never regenerated by verify), C6 judgment artifacts are the audit trail, C3 quarantine is not knowledge. Every derived layer gets a regenerate-and-diff check (the `_index.md` rule: KB006/KB014 today, extended to every future projection).
2. **Lifecycle is note-granular**: frontmatter lifecycle works exactly while *unit of versioning = unit of citation = unit of lifecycle*. The precise line, drawn after review: **lifecycle** (validity, supersession, status) is note-level only; **per-citation observation attributes** (`hash`, `retrieved`, liveness, support verdicts, provenance class) are *not lifecycle* — they are C5 observations about the note's source list, carry no independent validity interval, and are replaced by later observations with history in git. Claim-level *lifecycle* remains refused; a fact needing its own lifecycle becomes its own note — the split is performed by the gated verbs (a promote/migrate operation), with inbound links re-pointed under link checking, and it is expected to be rare (unbounded fragmentation would fight invariant 5).
3. **Supersession has one authoritative direction**: `superseded_by` on the old note is authoritative; the successor's `supersedes` is a checked, derivable convenience (reciprocity enforced, cycles refused, fan-in permitted — two notes may be superseded by one). Superseded notes remain in the working tree, leaned to a pointer; full text lives in git history.
4. **The token tax**: the primary consumer is a model reading the file — live notes stay lean; history is pointed to, never embedded.
5. **No vouched world-time metadata.** The earlier "unless the source states them" carve-out is corrected — a source-stated date is still a world-time claim verify cannot check. The rule: world-time statements enter as **attributed claims bound to a citation** ("per [source], effective 2026-03-01") in prose or C5 evidence, never as frontmatter fields the system vouches for.
6. **"Rebuildable from files+git" has a git-input contract**: rebuilds may read only the checked-out tree (shallow-clone safe); anything needing history depth must say so and cannot be a verify input. History preservation (no squash of canon-bearing branches) is a stated governance preference, not a mechanical guarantee.

## Consequences

- "Refresh with history maintained" = git (transaction time) + note supersession + C5 observation history — not per-fact timestamps.
- The vendor-named ceilings are *acknowledged with gates*, not answered: retrieval at scale → ADR-007's eval-triggered rungs; fact-level temporality → refused at this substrate, revisited only if a derived claim-index (with its own canonical-identity design) is ever justified; concurrent multi-writer → out of scope at this gear (sequential multi-agent writes through the gate are in scope — the distinction ADR-001's founding force refers to).
