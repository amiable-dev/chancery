## Context

The architecture review (packets 1–4) treated security and QA as design properties but never examined the layer below the documents. An audit found: six runtime dependencies chosen without a security review (including `jsdom`, a large HTML parser fed hostile web content); a CI workflow whose contract step **could not fail** (`verify | tee` under GitHub's implicit no-`pipefail` shell — caught by packet 5, the exact defect class this ADR exists to govern); tag-pinned actions on a single EOL Node line; and none of the public-repo hygiene a Gear 2 flip requires.

The archetype is the owner's [llm-council](https://github.com/amiable-dev/llm-council) DevSecOps stack (its ADR-035). Currency was verified 2026-08-22 (each claim carries that date as its review trigger): Scorecard actively maintained (v5.5.0 April 2026; [v6 roadmap is additive](https://github.com/ossf/scorecard/pull/4952)); SHA-pinning remains the canonical mitigation for the tag-rewrite attack class — `tj-actions/changed-files` (2025) and the Trivy ecosystem compromise ([CVE-2026-33634](https://github.com/advisories/GHSA-69fq-xp46-6x23), March 2026: 76 of 77 `trivy-action` tags force-pushed to credential stealers, CISA KEV, CVSS 9.4); CodeQL analyses Actions workflows as a language. The archetype is sized for a Python service + published package; this ADR right-sizes it for a Node CLI + corpus, and packet 5's review of the first draft is incorporated throughout.

## Decision

1. **Runtime: supported-LTS policy, enforced at the gate, not on developer machines.** `engines: "22.x || 24.x"` (exact LTS union, not an open floor) + `engine-strict` in `.npmrc` + `.nvmrc` as conveniences — and the **control**: `kb.mjs` asserts the floor at startup and refuses below Node 22 with a structured message, because harnesses supply their own Node and the CLI must defend itself (this resolves the reviewed tension with §4's "parity lives at the gate" — the gate *is* the enforcement point; nvm files are ergonomics). CI matrix tests 22 and 24 on ubuntu (macOS on main only — the 10× minute multiplier is not spent per feature push). **The floor moves via the scheduled `node-eol` job** ([check-node-eol.mjs](../../.kb/bin/check-node-eol.mjs) carries the EOL dates as data and fails when the matrix holds a dead line) — the earlier "dependabot-prompted" claim was wrong; no such ecosystem exists. Windows: unsupported, trigger = first real user demand.
2. **Dependency posture: position *and* behaviour.** Gate-path modules may import only Node builtins + `yaml` + `ajv`/`ajv-formats`; the extraction stack (`jsdom`, `@mozilla/readability`, `turndown`) is **dynamically imported by the network verbs only**. The conformance suite's purity test walks the static import graph from `bin/kb.mjs` (entry point named; dynamic `import()` is the sanctioned escape and appears only in the two network-verb modules) — and the offline CI leg (`verify` under `unshare -rn`) proves the gate makes no network call at runtime. **Stated at its true strength** (per review): this establishes that *the CI verify process* imports a minimal set and touches no network; `kb ingest` still runs extraction in-process, so its **behavioural hardening** is part of this decision: [net-guard.mjs](../../.kb/lib/net-guard.mjs) enforces an http(s)-only scheme allowlist, private/link-local/metadata-address denial (SSRF), re-checks the post-redirect URL, caps responses at 5MB; jsdom runs with scripts and external resource loading off (its defaults, now load-bearing and stated). Subprocess isolation for extraction is the next hardening rung, triggered by any evidence of jsdom parser exploitation in the wild. New **runtime** dependencies need an ADR-noted reason; dev dependencies get the same rule **whenever they execute in a workflow** (the blanket exemption was reviewed out — CI blast radius is identical).
3. **CI hardening + install-time supply chain** (the half the first draft missed): every action SHA-pinned with version comments, dependabot maintaining pins; top-level `permissions: contents: read` with per-job elevation (scorecard.yml's former `read-all` was an unrecorded exception — removed); `persist-credentials: false`; fork-safe layering; `timeout-minutes` and `concurrency` on every workflow. Install-time: **CI always runs `npm ci --ignore-scripts`** (no dependency lifecycle script executes in any workflow; none of the six deps needs them); `npm audit --package-lock-only` (audits without installing); **dependabot cooldown 7 days** (a hijacked release's most dangerous week is its first); gate-path deps arrive as individual PRs, extraction-stack minors/patches grouped, majors always individual; grouped updates never auto-merged; pin bumps reviewed by reading the upstream diff.
4. **Scanning stack — adopt / defer / reject, each with a live reason:**
   - **Adopt now (private-repo-compatible)**: dependabot updates + **vulnerability alerts + dependency graph (enabled today — they work on private repos; deferring them was a reviewed error)**; gitleaks (verified license-free: `amiable-dev` is a User account; weekly run sweeps full history); weekly `npm audit`; **zizmor** (workflow-security lint — the detector for this file's own defect class during the private phase; pinned, dated review trigger in operations.md); the `verify-offline` network-namespace leg; the `pr-contract` check; the `gate` aggregate.
   - **Adopt, arms at the public flip** (needs public-or-GHAS): CodeQL (`javascript-typescript` security-extended + `actions` default suite; push+schedule — per-PR CodeQL is redundant at this size), dependency-review (vulnerability **and licence** halves), Scorecard with published results. Guards are **fail-closed** (a `precheck` job resolves visibility via the API — the naive `github.event.repository.private == false` expression is fail-open on schedule payloads) and are **never deleted**: they start passing at the flip. `workflow_dispatch` dry-runs both before flip day. **Accepted interim risk, dated 2026-08-22**: no deep JS SAST until the flip; interim = zizmor + purity test + audit/dependabot.
   - **Defer with trigger**: SBOM + SLSA provenance + release workflow → first tagged release (artifact defined in operations.md now); CITATION.cff, SUPPORT.md → the flip PR; GOVERNANCE.md → a second maintainer; **actionlint** → a pinned, checksummed one-line install (no npm/PyPI-native distribution today; zizmor covers the security half meanwhile); subprocess extraction isolation → §2's trigger.
   - **Reject with reason**: **Semgrep** — interim workflow coverage now exists (zizmor) and the JS gap is a *named dated risk* rather than a silent one; revisit if the risk ages past the flip. **SonarCloud, Snyk** — SaaS token surface, duplicative for six dependencies. **Trivy** — *duplication*: `trivy fs` would scan the same lockfile npm audit + dependabot already cover (the first draft's "nothing to scan" was factually wrong — reviewed and corrected; wrong reasons rot worse than no reasons). **Pre-commit hooks** — parity lives at the gate (and §1 now honours that principle by putting the Node floor *in* the CLI).
5. **Server-side settings are the flip-day gate**, rehearsable and ordered (operations.md): dry-runs, full-history secret sweep, history content review, fork-safety Actions settings, branch protection from the committed [branch-protection.json](../../.github/branch-protection.json) with **`gate` as the single required context** (never matrix-leg names), read-back verification, then the irreversible visibility change. **Named exception to invariant 8, stated here and in operations.md**: `enforce_admins: false` + single-maintainer direct push means the sole admin bypasses the server-side gate; every non-admin path is bound; Scorecard will report it; the exception retires when a second maintainer arrives (same trigger as GOVERNANCE.md).
6. **Repository governance files**: SECURITY.md (email is the **live** channel today; private vulnerability reporting becomes preferred *at the flip* — the first draft advertised a button that didn't exist); CONTRIBUTING.md (write-paths PR contract, verify-before-push, pin-bump review rule, no-auto-merge rule, single-maintainer governance note); PR template walking the contract; CODEOWNERS — **documentary until required reviews exist** (stated; ownership metadata enforces nothing for a solo maintainer). The *control* for the fixtures-and-checks-together attack shape is the `pr-contract` CI check, which flags gate-code + fixture changes in one PR (a tripwire, not a lock, at this gear).
7. **Versioning**: Conventional Commits; semver 0.x; CHANGELOG at first tag; 1.0 criterion and npm-publication trigger in operations.md; `--provenance` mandatory whenever publishing starts. LICENSE: MIT, attribution confirmed by the owner before the flip (tracked in the flip checklist).

## Consequences

- The gate is now falsifiable end-to-end: exit codes real, report asserted by a tested script, offline leg proving hermeticity, one aggregate required check that survives matrix renames.
- The supply chain is governed at both moments that matter — what runs *as* CI (pins, permissions) and what executes *during* install (`--ignore-scripts`, cooldown, lock-only audit).
- Everything rejected or deferred carries a reason that is *currently true* and a dated trigger — packet 5 demonstrated that a wrong reason ("nothing to scan") and a dead mechanism ("dependabot-prompted") are worse than none, and both are now fixed in place.
- The maintainer's own machine is out of policy on Node 20 and the CLI now says so at startup; `mise`/`nvm` already hold 22/24 locally, so the fix is a default switch, not an install.
