# Context Compilation Pattern — Flashcards

#flashcards/ai-agents

## Definition <!-- kb:card:f3b669 -->
What is the Context Compilation Pattern?
?
A build-time governance framework that constrains AI code generation via two layers: (1) structured injection of versioned governance artifacts (intent, boundaries, threat models) into the agent prompt before inference, and (2) post-generation deterministic static analysis (Semgrep/AST checks) that makes declared boundary violations impossible to merge.

## Dual Enforcement <!-- kb:card:a1ed96 -->
What are the two enforcement layers in the Context Compilation Pattern, and what does each do?
?
**Soft enforcement** — governance artifacts in the prompt bias the LLM toward compliant generation.
**Hard enforcement** — Semgrep/AST rules in CI deterministically reject any generated code that violates declared boundaries. The hard layer is immune to LLM probabilistic failure.

## Context Artifacts <!-- kb:card:dfaf57 -->
What four files are authored per bounded context in the Context Compilation Pattern?
?
1. `intent.md` — what the module is for, in plain language
2. `boundaries.md` — structural invariants for the LLM (forbidden imports, allowed communication paths, dependency direction)
3. `threat-model.md` — adversarial constraints as declarative abuse scenarios (prompt injection, secrets exfiltration)
4. `semgrep-rule.yml` — deterministic CI rule paired with `boundaries.md`, authored by humans, not generated by AI

## Boundary Hierarchy <!-- kb:card:4227e3 -->
What is the precedence order for resolving conflicting constraints in the Context Compilation Pattern?
?
**Threat model > Boundaries > Coding standards > Intent + acceptance criteria**
Resolution is deterministic CI rejection, not LLM reasoning. If a feature request conflicts with a boundary, the build fails and the developer must reconcile them explicitly before regeneration.

## Relationship to Prompt Engineering <!-- kb:card:54ed69 -->
How does the Context Compilation Pattern differ from prompt engineering?
?
Prompt engineering asks a probabilistic model for a better answer.
The Context Compilation Pattern mechanically constrains what the model is *allowed to generate* and deterministically *rejects* non-conformant output via static analysis. It's a compiler for the agent's context, not a better instruction set.

## Application <!-- kb:card:e9aa66 -->
Give a concrete example of a context artifact pair in action.
?
`boundaries.md` declares: *"Zero external network I/O is allowed in the billing domain."*
`semgrep-rule.yml` blocks `import smtplib` and `import requests` in `src/billing/**` with ERROR severity.
The human writes the Markdown; CI enforces the YAML. The LLM reads the natural language; the CI runner executes the rule.
